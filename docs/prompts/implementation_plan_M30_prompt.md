Milestone 30: Metadata & DocumentationObjectiveTo add a layer of documentation to the simulation. This allows users to name specific components (e.g., "Main Ingestion Source") and describe their logic, as well as define a global name and description for the entire model.Core Mechanics1. Entity-Level MetadataNew Properties: Every GamePart will now utilize two reserved property keys:custom_name: (String) A user-defined label.custom_description: (String) A longer text explanation.UI Inspector Logic: The EditorUI (specifically rebuild_left_inspector) will be updated to always place these two fields at the very top of the list, regardless of other properties.Dynamic Labels: If an object has a custom_name, that name will appear in the UI header instead of the generic variant_key.2. Global Model Metadata (The Flow)Storage: The LevelManager will be updated to include a metadata header in the YAML output:metadata:
  flow_name: "Supply Chain V1"
  flow_description: "Automated routing for the western region."
entities: [...]
Global Access: The game_state will store flow_name and flow_description.Flow Settings UI: A new "Flow Settings" button in the Top UI bar will open a dedicated panel (or repurpose the Inspector) to edit these global strings.3. PersistenceLevelManager.save_level: Will accept optional metadata arguments to write to the file.LevelManager.load_level: Will return a tuple/dictionary containing the metadata alongside the entity lists.BenefitsCollaborative Clarity: When sharing levels, other users can click objects to see exactly what they are intended to do.Project Organization: Makes the "Saves" folder more readable by allowing models to self-identify their purpose.Professional Finish: Moves the project closer to being a functional "Logic/Data Flow" editor.
